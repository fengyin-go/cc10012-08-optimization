# 多维数据探查分析工具

离线版多维数据探查分析工具，涵盖数据源接入、交互查询、聚合统计、图表看板、预警通知与数据导出，所有分析配置与结果持久化到浏览器本地存储。

这是一个**纯前端**管理平台：Vue 3 + Vite + TypeScript，仓库里没有后端服务。业务数据由
`frontend/src/data/` 下的本地数据层提供：首次打开用示例数据播种，之后的登记、筛选与状态流转
结果都持久化在浏览器 `localStorage` 里，刷新或重开浏览器都还在。dev server 已关掉自动打开页面，
启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 Vue 3 + Vite + TypeScript 前端（唯一运行单元）
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/local-service.ts   本地数据服务：列表、筛选、动作流转、导出
│   ├── src/data/             模块元数据 / 示例数据 / localStorage 持久化
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false，无 /api 代理）
├── .gitignore
└── docker-compose.yml
```

## 启动

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，需要自己访问。

生产构建：

```bash
cd frontend
npm run build
```

## 约定

- 每个模块的页面在 `frontend/src/views/<模块>/index.vue`，页面只负责渲染，读写统一走
  `frontend/src/api/local-service.ts`。
- 字段、状态、动作与流转目标集中在 `frontend/src/data/modules.ts`；示例数据在
  `frontend/src/data/seed.ts`。
- 状态流转只允许在 `local-service.ts` 里改，页面组件不做业务判断。
- 想回到初始数据：清掉浏览器里 `data-explore-studio:entries` 这一项，或调用 `resetModule(模块)`。

## 聚合结果数据集（复用、重算与归档）

聚合计算域在通用条目之外，还有一套独立的「聚合结果数据集」数据层，位于
`frontend/src/data/aggregate/`，持久化在浏览器 `data-explore-studio:aggregate-datasets` 键：

- `standards.ts`：阈值、取值范围、判定条件、精度规则、状态枚举的唯一业务标准，
  页面、引擎、导出、归档共用同一套口径，并随数据集冻结快照归档。
- `source-data.ts`：取数链路入口，分组统计从这里读取目标字段；来源指纹参与缓存键，
  源数据变化后旧缓存不可能继续命中。
- `engine.ts`：缓存键构造（方案编号+方案版本+精度+时间窗口+来源指纹+分组+标准版本）、
  按分组维度的重算范围评估、逐组复用/重算判定。缓存时间到期与方案版本更新同时发生时，
  旧精度结果一律不命中；任一分组失败即整体失败，绝不产出半组数据。
- `aggregate-service.ts`：编排取数链路与原子提交——每次成功提交只写入一份生效数据集，
  旧数据集整体移入归档；重算失败只留失败痕迹，上一份完整数据集继续生效。
- `archive.ts`：聚合结果数据集输出标准 ZIP 归档（方案快照、业务标准、按精度拆分的分组
  CSV、重算留痕、清单、完整数据集 JSON），并支持读回复核；导出清单与聚合明细页共用
  同一个分组行构造器，字段、行数完全一致，不同精度的组绝不拼在同一个文件里。

同窗口存在两位小数历史结果又收到四位小数新请求时，默认「双精度并存」：两组精度都保留、
各自带精度依据与重算范围，也可切换为「统一新精度」（旧精度随归档留痕），两种权衡都写入
重算留痕。AGGR-0003 把 10 分钟窗口改为 30 分钟时，仅新旧两个窗口的分组重算，60 分钟等
其他窗口继续沿用原结果。

